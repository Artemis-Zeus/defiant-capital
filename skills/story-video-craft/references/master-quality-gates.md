# 母稿强制验收

生成或修改 `script/master.md` 后逐项执行。先处理阻塞项，再处理编辑建议。没有实际完成的项目不得勾选。

## A. 研究与事实门禁

以下任一失败都阻塞交付：

- [ ] 核心结局、时间、规模和法律状态在 `04-claims.md` 有明确状态。
- [ ] 架构稿中每个事实段都绑定 C###。
- [ ] 每个 C### 都能在 `03-sources.md` 找到支持它的 S###。
- [ ] 关键行动前“人物当时知道什么”有来源；没有则不写“明知、故意、早已知道”。
- [ ] 所有直接引语回查原文；无法回查时改为概述。
- [ ] “被指控、被起诉、被判决／裁定、承认、和解、媒体报道”没有混用。
- [ ] 争议、线索和资料不足没有被写成定论。
- [ ] 外文材料的译文没有改变限定语、主语和时间范围。

运行：

```bash
python3 scripts/audit_claims.py topics/active/<slug>
```

退出码非 0 时停止，不写“已完成”。

## B. 故事承载门禁

- [ ] 只有一个绝对主角或连续冲突承载者。
- [ ] 能用一句具体因果链概括全片，不使用“人性、时代、资本逻辑”作空泛连接。
- [ ] 开场异常、最大反转、最终代价都属于同一主线。
- [ ] 每名重要配角通过行动改变承载者处境。
- [ ] 删除任何一个章节都会损失一个必要因果节点；否则合并或删除。

## C. 因果门禁

逐章填写：

| 章节 | 进入局面 | 本章动作 | 新局面 | 下一章为何必须发生 | 结果 |
|---|---|---|---|---|---|

判定：

- [ ] 每章有动作，不只介绍背景。
- [ ] 每章有可描述的状态变化。
- [ ] 本章结果是下一章输入。
- [ ] 因果没有把先后发生误写为相互导致。
- [ ] 多因问题没有被压成单一责任或单一人格。

任意连续两章只能用“后来又发生”连接时，因果链不合格。

## D. 开场门禁

- [ ] 第一段包含具体时间／环境、对象、动作和异常结果。
- [ ] 观众无需背景也能说出“谁遇到了什么问题”。
- [ ] 前 45 秒尽量不要求记住超过两名新人物。
- [ ] 没有“今天我们讲”“他到底是谁”“这一切为什么”等口头自问自答。
- [ ] 栏目、片名或宏观背景出现在故事承诺之后。
- [ ] 开场没有泄露本应保留的最终解释，也没有隐瞒当前理解所需条件。
- [ ] 已登记结尾如何重新解释开场。

## E. 背景与参照门禁

为每段背景填写其回收动作：

| 背景段 | 后来改变谁的选择／资源／判断 | 回收位置 | 无回收则处理 |
|---|---|---|---|

- [ ] 人物生平只保留后来成为技能、人脉、激励或限制的部分。
- [ ] 组织历史只保留后来解释目标、承诺、资源或路径依赖的部分。
- [ ] 陌生地点、机构和金额首次承担戏剧功能前有最小参照。
- [ ] 数字有分母、比较对象、容器或行动后果。
- [ ] 没有为了展示研究量而堆资料。

## F. 信息释放与悬念门禁

- [ ] 每章有一个可回答的阶段问题。
- [ ] 章末推动来自局面变化，不靠另加空泛问句。
- [ ] 隐藏的是答案，不是人物当前拥有的信息或法律事实。
- [ ] 反转在前文有可回查迹象。
- [ ] 反转由证据支持，不靠新增未证事实。
- [ ] 连续阶段目标使用不同的主要失败／成功机制。
- [ ] 已知结局没有被伪装成实时未知。

## G. 机制门禁

- [ ] 一个机制段只解释一个机制。
- [ ] 正常功能、变化动作、人物后果三项齐全。
- [ ] 长视频单个机制段原则上不超过 90 秒。
- [ ] 机制之后立即回到人物或项目行动。
- [ ] 术语只在影响下一步时保留。
- [ ] 画面更适合承接的结构、地图和比较已标入架构稿或 `shots.md`。

机制无法落实到“谁因此要做什么”时，从旁白删除。

## H. 人物与风险门禁

- [ ] 主角目标、资源、选择和代价以可观察事实表达。
- [ ] 没有把童年、疾病、残障、贫困、政治身份或民族背景写成行为的必然原因。
- [ ] 没有自行诊断人格、智力或精神状态。
- [ ] 当事人自述标为其声称，未升级为事实。
- [ ] 受害者、失败者和配角没有被纯粹工具化。
- [ ] 犯罪、死亡、灾难和群体身份没有只被用作笑点。

## I. 语言与口播门禁

- [ ] 正文没有 C###、S###、URL、镜头指令、审校备注或平台互动文案。
- [ ] 每章末只有来源名称与年份的引用块。
- [ ] 一句尽量只承担一个动作或判断。
- [ ] 长句已按自然换气拆分。
- [ ] 时间跳跃有年份、日期或明确连接。
- [ ] 专名首次出现立刻跟身份／功能。
- [ ] 评价晚于事实关系，且没有改写证据含义。
- [ ] “第一、第二、第三、综上、由此可见、这说明、换句话说”等报告腔已逐句检查。
- [ ] 实际朗读已记录问题；没有朗读时状态只能是初稿。

运行：

```bash
python3 scripts/audit_voiceover.py topics/active/<slug>/script/master.md
```

逐项处理警告，但不要为了数字漂亮破坏准确性。

## J. 铺垫与结尾门禁

- [ ] 每项重要铺垫都有动作层回收。
- [ ] 回收改变能力、资源、判断、风险或关系，而非单纯重复词语。
- [ ] 结尾先落人物／项目处境。
- [ ] 结尾回到开场同一动作、物件、态度或判断。
- [ ] 中段因果使开场获得具体的新解释。
- [ ] 只有一次主题判断。
- [ ] 主题判断后停止，没有第二结尾和新机制。

## K. 画面交接门禁

- [ ] 每个段落已标记主要画面任务：证据、定位、解释、演绎或评价。
- [ ] 旁白省略的参照系在 `script/shots.md` 有承接。
- [ ] 替代画面标“示意”，不会被误认成原始影像。
- [ ] 画面素材在 `06-visual-assets.md` 有来源和版权状态。
- [ ] 影视梗、反应图和补充字没有遮蔽关键事实。
- [ ] 时间跳跃有年份卡、地图或其他视觉桥。

## L. 原创性门禁

全文搜索并人工检查：

- [ ] 没有参考作者口头禅、固定句式组合、栏目名称或品牌称呼。
- [ ] 没有复制参考作者的标题句法。
- [ ] 没有参考作者标志角色、猫形象、反复梗或特有画面包装。
- [ ] 没有模仿具体声线、尾音、口音、停顿或表演身份的指令。
- [ ] 幽默由本题材事实关系产生，不依赖移植原片包袱。
- [ ] 删除所有参考作者名字后，稿件的因果、表达和笑点仍然成立。
- [ ] 与参考样本相似之处能明确说成抽象方法，而不是措辞或表达组合。

## M. 商业段门禁

默认不适用。只有用户明确要求加入广告时检查：

- [ ] 商品资料、健康／性能、销量、奖项、评价、肖像和价格均有可用证明与授权。
- [ ] 商业身份清楚。
- [ ] 进入桥来自邻接词、物件或关系，没有利用悲剧或脆弱处境。
- [ ] 退出后一两句重新给时间、地点、人物处境或未解目标。
- [ ] 删除整段后主线语义完全连续。
- [ ] 商业段没有承担唯一的关键事实或转折。

## 验收结论格式

```markdown
状态：初稿 / 待事实修复 / 待风险审校 / 待试录 / 可进入分镜

阻塞项：
- 位置｜问题｜需要回到的文件或 C###

主要编辑建议：
- 位置｜观众问题｜具体改法

结构证据：
- 一句话因果链：
- 分支：
- 开场问题：
- 最大反转：
- 三项关键回收：
- 结尾对开场的新解释：

自动检查：
- audit_claims：
- audit_voiceover：

下一步：
```

“可进入分镜”只表示文本与证据门禁通过，不表示成片定稿；仍需镜头对齐、实际试录和观感评估。
