# 资本故事叙事生产规约 V1.0

本规约沉淀橙县题材V0.1—V0.5的可复用经验，约束“题材研究 → 人物化母稿 → 实际口播稿”流程。个案结构不得冒充通用公式。

## 一、版本演进留下的结论

| 阶段 | 暴露的问题 | 可复用结论 |
|---|---|---|
| V0.1 | 资料和机制完整，故事仍零散 | 资料齐全不等于故事成立 |
| V0.2 | 有人物阵容，章节仍由机构和机制推动 | 有人物名单不等于人物叙事；配角必须通过行动改变主角处境 |
| V0.3 | 钩子和章节悬念增强，仍带报告体 | 章节应按主角的连续选择组织，不按机构、机制或责任分类 |
| V0.4 | 母稿口语化后才接近可录制状态 | 编辑母稿与实际口播稿必须分层 |
| V0.5 | 人物和数字已有，观众仍不知道事件分量 | 关键名词和数字首次承担戏剧功能前，必须建立最小参照系 |

## 二、项目硬规约

1. 一条视频只讲一个故事和一条连续因果链。
2. 详细研究前确定绝对主角；群像题材也要有共同目标或冲突中心。
3. 每个重要配角必须承担可观察功能：协助、许可、供给、警告、催债或承担代价。
4. 背景、制度和金融机制只有在改变人物选择或帮助观众判断分量时进入正文。
5. 不虚构对白、心理活动、私人关系、未证实动机或分钟级场景。
6. 数字、法律结论、关键人物行动和核心背景必须能通过`C###—S###`反向定位。
7. 冷开场可以倒挂结局；进入正文后默认顺叙，必要跳时必须给明确坐标。
8. 一段最多解释一个新机制，解释后立即回到人物行动与后果。
9. 一期只保留一个最终主题落点，避免清算、责任、机制和升华连续形成多个结尾。
10. 不移植其他创作者的口头禅、固定梗、标题句法或标志性表达。
11. 编辑母稿保留证据和法律限定；朗读净稿另存`script/voiceover.md`，不得覆盖母稿。
12. 背景不是百科前言；只回答“这是谁、这里多大、钱有多重、当时为什么诱人”。

## 三、研究必须同时收集的叙事数据

每名核心人物至少回答：

| 字段 | 研究问题 |
|---|---|
| 身份与资源 | 他掌握什么权力、资金、关系或信息？ |
| 目标与激励 | 他当时想得到什么？有什么现实压力？ |
| 当时所知 | 他在作决定前已经知道什么？ |
| 可选方案 | 是否有人警告？能否停下、降险或换路？ |
| 实际行动 | 他具体批准、拒绝、购买、出售、披露或隐瞒了什么？ |
| 后果与关系反转 | 这个行动让谁加入、退出、翻脸或承担损失？ |

题材背景另收集四种参照：

- **实体参照：** 这家公司、地区或机构是什么体量，不是什么。
- **时代参照：** 当时的经济、技术、监管或社会条件。
- **数字参照：** 核心金额相对本金、收入、预算、用户或行业规模有多大。
- **选择参照：** 当时有哪些真实替代方案，不能用事后知识伪造容易选择。

核心资料不仅要证明结局，还要证明主角的关键选择及其作选择时可见的信息。

## 四、通用人物因果链

以下是检查问题，不是固定章节：

> 主角获得一次成功  
> → 成功带来信用与资源  
> → 主角扩大下注  
> → 警告或替代方案出现  
> → 主角作出不可逆选择  
> → 外部条件改变  
> → 配角关系反转  
> → 代价落地  
> → 用人物命运完成一次主题收束

题材若不符合这条链，应按事实重建，不得硬套“预警者”“落选者”或破产结构。

## 五、母稿门禁

- 冷开场交付：一个人或冲突中心、一件离谱结果、一个未回答的问题。
- 前45秒尽量不要求观众记忆超过两名新人物。
- 每章同时包含人物行动、局面变化和下一问。
- 配角首次出现即做事，不先念角色说明书。
- 核心数字控制在3—5组；其他数字只在改变判断时出现。
- 时间跳跃必须有年份、日期或“此前/随后”等坐标。
- 法律限定语不得删除；冗长程序细节可移到编辑注或字幕层。
- 机制段落结束后，下一段必须回答“谁因此要做什么”。
- 结尾先落人物命运，再给一次主题判断，之后停止。

## 六、口播转换门禁

`script/master.md`是编辑母稿，`script/voiceover.md`是主播实际朗读稿。转换时：

1. 保留事实含义、归因和法律状态，删除可见证据编号及编辑说明。
2. 把长句拆成自然换气单位；一句尽量只承担一个动作或判断。
3. 删除“第一、第二、第三”“这说明”“换句话说”等报告式连接词，除非确实帮助理解。
4. 把抽象名词改写为人物、动作和后果；无法改写时检查该句是否必须口播。
5. 每20—30秒检查是否出现人物动作、局面变化、具体例子或新问题。
6. 对陌生地点、机构和金额建立最小参照，不另开百科支线。
7. 完成一次实录朗读再定稿；文本统计只发警报，不替代听感判断。

## 七、自动审计

```bash
python3 scripts/audit_claims.py topics/active/<slug>
python3 scripts/audit_voiceover.py topics/active/<slug>/script/voiceover.md
```

- `audit_claims.py`检查主张和来源编号是否闭合、母稿是否引用未知编号。
- `audit_voiceover.py`统计句长、长句、报告腔、数字密度与年份跳跃。
- 脚本输出是编辑提示；除编号闭合外，不把统计阈值当作硬性文风标准。

## 八、不应固化的个案解法

不得把以下内容写成项目公式：固定七章、固定18—21分钟、必须设置预警者、必须倒叙、必须使用“成绩单”意象、必须模仿某位创作者。它们只能在具体题材中经证据和听感验证后采用。
