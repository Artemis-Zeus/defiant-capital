# 资本故事叙事生产规约 V1.0

本规约沉淀橙县题材V0.1—V0.5的可复用经验，约束“题材研究 → 人物化母稿 → 实际口播稿”流程。个案结构不得冒充通用公式。

## 一、版本演进留下的结论

| 阶段 | 暴露的问题 | 可复用结论 |
|---|---|---|
| V0.1 | 资料和机制完整，故事仍零散 | 资料齐全不等于故事成立 |
| V0.2 | 有人物阵容，章节仍由机构和机制推动 | 有人物名单不等于人物叙事；配角必须通过行动改变主角处境 |
| V0.3 | 钩子和章节悬念增强，仍带报告体 | 章节应按主角的连续选择组织，不按机构、机制或责任分类 |
| V0.4 | 母稿口语化后才接近可录制状态 | 编辑母稿与实际口播稿必须分层 |
| V0.5 | 人物和数字已有，观众仍不知道事件分量 | 关键名词和数字首次承担戏剧功能前，必须建立最小参照系 |

## 二、项目硬规约

1. 一条视频只讲一个故事和一条连续因果链。
2. 详细研究前确定绝对主角；群像题材也要有共同目标或冲突中心。
3. 每个重要配角必须承担可观察功能：协助、许可、供给、警告、催债或承担代价。
4. 背景、制度和金融机制只有在改变人物选择或帮助观众判断分量时进入正文。
5. 允许模拟对白、场景演绎等剧情化手法增强叙事；演绎不是证据：不得改变事实的因果关系与已知时间顺序，不得把编造的话写成有出处的真实引语；私人关系与未证实动机仍不得虚构。
6. 数字、法律结论、关键人物行动和核心背景必须能通过`C###—S###`反向定位。
7. 冷开场可以倒挂结局；进入正文后默认顺叙，必要跳时必须给明确坐标。
8. 一段最多解释一个新机制，解释后立即回到人物行动与后果。
9. 一期只保留一个最终主题落点，避免清算、责任、机制和升华连续形成多个结尾。
10. 不移植其他创作者的口头禅、固定梗、标题句法或标志性表达。
11. 题材正文只分两层：架构稿（`05-story-outline.md`，绑定`C###`）与口播稿（`script/master.md`）；口播稿正文不出现编号，各章末用引用块列出本章来源名称（不写URL）。
12. 背景不是百科前言；只回答”这是谁、这里多大、钱有多重、当时为什么诱人”。
13. 每个题材建立镜头文档`script/shots.md`，以口播段落为锚登记画面、素材类型、屏幕文字与版权引用；旁白不承担的参照系（体量、地理、职务解释）必须由镜头文档显式承接。

## 三、研究必须同时收集的叙事数据

每名核心人物至少回答：

| 字段 | 研究问题 |
|---|---|
| 身份与资源 | 他掌握什么权力、资金、关系或信息？ |
| 目标与激励 | 他当时想得到什么？有什么现实压力？ |
| 当时所知 | 他在作决定前已经知道什么？ |
| 可选方案 | 是否有人警告？能否停下、降险或换路？ |
| 实际行动 | 他具体批准、拒绝、购买、出售、披露或隐瞒了什么？ |
| 后果与关系反转 | 这个行动让谁加入、退出、翻脸或承担损失？ |

题材背景另收集四种参照：

- **实体参照：** 这家公司、地区或机构是什么体量，不是什么。
- **时代参照：** 当时的经济、技术、监管或社会条件。
- **数字参照：** 核心金额相对本金、收入、预算、用户或行业规模有多大。
- **选择参照：** 当时有哪些真实替代方案，不能用事后知识伪造容易选择。

核心资料不仅要证明结局，还要证明主角的关键选择及其作选择时可见的信息。

## 四、通用人物因果链

以下是检查问题，不是固定章节：

> 主角获得一次成功  
> → 成功带来信用与资源  
> → 主角扩大下注  
> → 警告或替代方案出现  
> → 主角作出不可逆选择  
> → 外部条件改变  
> → 配角关系反转  
> → 代价落地  
> → 用人物命运完成一次主题收束

题材若不符合这条链，应按事实重建，不得硬套“预警者”“落选者”或破产结构。

## 五、母稿门禁

- 冷开场交付：一个人或冲突中心、一件离谱结果、一个留在观众心里的问题。问题必须由荒谬场景与信息反差自然生成（如"最富裕的县破产了"本身即问题），旁白不得口头抛出"到底是谁/为什么"式提问，也不得自问自答。
- 前45秒尽量不要求观众记忆超过两名新人物。
- 每章同时包含人物行动、局面变化和下一问。
- 配角首次出现即做事，不先念角色说明书。
- 核心数字控制在3—5组；其他数字只在改变判断时出现。
- 时间跳跃必须有年份、日期或“此前/随后”等坐标。
- 法律限定语不得删除；冗长程序细节可移到编辑注或字幕层。
- 机制段落结束后，下一段必须回答“谁因此要做什么”。
- 结尾先落人物命运，再给一次主题判断，之后停止。

## 六、口播稿门禁

每个题材只维护架构稿（`05-story-outline.md`）与口播稿（`script/master.md`）两层，不再另存净稿。口播稿要求：

1. 事实含义、归因和法律状态以架构稿与事实矩阵为准；正文不出现`C###`/`S###`编号。
2. 每章末尾用引用块列出本章来源：只写来源名称（站点/书籍/报道/期刊名＋年份），不写URL、不写编号。
3. 把长句拆成自然换气单位；一句尽量只承担一个动作或判断。
4. 删除”第一、第二、第三””这说明””换句话说”等报告式连接词，除非确实帮助理解。
5. 把抽象名词改写为人物、动作和后果；无法改写时检查该句是否必须口播。
6. 每20—30秒检查是否出现人物动作、局面变化、具体例子或新问题。
7. 对陌生地点、机构和金额建立最小参照，不另开百科支线。
8. 完成一次实录朗读再定稿；文本统计只发警报，不替代听感判断。
9. 旁白与画面分工：口播刻意省略的参照系，必须登记进`script/shots.md`由画面承担，两侧都不出现的参照系视为缺口。

## 七、镜头文档门禁

每个题材在`script/shots.md`维护镜头文档，与口播稿逐段对齐：

1. 以口播章节/段落为锚（镜号＋口播首句），逐镜登记：画面内容、素材类型（历史影像/自制示意/字幕卡/图表）、是否替代画面、屏幕文字与字幕卡、时长估算。
2. 替代画面必须标注"示意"，不得伪装成事件原始影像；版权状态只引用`06-visual-assets.md`的登记，不在镜头文档重复。
3. 冷开场段的画面必须优先兑现字幕层承接的参照系（地点、体量、时代）。
4. 旁白跳时处（如硬切回溯），转场设计（年份卡、定格、匹配剪辑）由镜头文档承担。
5. 口播＋镜头组合的观感评估使用`skills/viewer-experience-review/SKILL.md`；评估对象是观众侧体验，不重复研究层的事实审计。

## 八、自动审计

```bash
python3 scripts/audit_claims.py topics/active/<slug>
python3 scripts/audit_voiceover.py topics/active/<slug>/script/master.md
```

- `audit_claims.py`检查事实矩阵的编号闭合（编号体系保留在架构稿与研究层，口播稿不出现编号）。
- `audit_voiceover.py`统计句长、长句、报告腔、数字密度与年份跳跃。
- 脚本输出是编辑提示；除编号闭合外，不把统计阈值当作硬性文风标准。

## 九、不应固化的个案解法

不得把以下内容写成项目公式：固定七章、固定18—21分钟、必须设置预警者、必须倒叙、必须使用“成绩单”意象、必须模仿某位创作者。它们只能在具体题材中经证据和听感验证后采用。
