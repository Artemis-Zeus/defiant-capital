# 给 AI 模型的资料交接与写作约束

## 1. 推荐输入顺序

向 AI 模型提供一个题材时，按以下顺序输入：

1. 本文件和 `docs/editorial-standards.md`；
2. `docs/narrative-production-standard.md`与对应项目skill；研究任务加读 `docs/source-collection-standard.md`；涉及抖音主站成片时加读 `docs/douyin-standard.md`；
3. 题材目录中的 `README.md`；
4. `01-brief.md`与`02-timeline.md`；
5. `04-claims.md`；
6. `03-sources.md`；
7. `07-risk-review.md`；
8. 已有提纲、母稿或口播稿；
9. 本轮具体任务与长度要求。

不要只丢一堆链接让模型自行猜测哪些事实可靠。

## 2. 模型必须遵守的硬约束

- 只能把“已交叉验证”或“权威定论”的关键事实写成确定性陈述。
- “存在争议”的内容必须展示争议双方与证据差异。
- “线索”与“待核验”不得进入定稿，除非明确作为未获证实的说法并且具有叙事必要性。
- 不得虚构事实、数字、引语、场景、对话、动机或来源。
- 不得把相关性写成因果。
- 无法确认时输出 `[需要核验：具体问题]`，不能用模糊措辞蒙混。
- 关键事实保留 `[Cxxx]` 标记，直到人工事实复核完成。
- 外文专名首次出现时提供原文；译名保持统一。
- 幽默不得改变事实含义，也不得依赖对受害者或无关群体的羞辱。

## 3. 推荐任务拆分

不要一次要求模型“从资料直接写完整爆款稿”。建议分为：

1. 找证据缺口与相互矛盾之处；
2. 提炼一句话故事承诺；
3. 生成三种故事结构并说明取舍；
4. 生成章节卡和每章证据编号；
5. 撰写母稿；
6. 对照事实表逐句审计；
7. 另存并转换为实际口播稿；
8. 实录朗读，调整节奏、幽默和口语化；
9. 生成平台包装与抖音主站成片文案（按 `docs/douyin-standard.md` 执行）。

## 4. 母稿输出格式

每章建议包含：

```markdown
## 章节标题

> 本章目的：
> 悬念：
> 关键事实：C001、C004
> 建议画面：V003、V007

旁白正文……
```

编辑母稿写入`script/master.md`并保留`[C###]`。主播净稿写入`script/voiceover.md`，删除可见证据编号和制作说明，但不删除归因、法律状态、数字口径和事实边界。

## 5. 事实审计提示词

```text
请把母稿中的每个可核验陈述，与 04-claims.md 和 03-sources.md 对照。
逐项输出：原句、对应事实编号、证据是否足够、是否存在措辞越界、建议改写。
如果资料中没有依据，明确标为“无支持”，不要自行补证。
```

## 6. 写作提示词骨架

```text
你正在为“逆天的资本”撰写长视频编辑母稿和实际口播稿。
目标风格：悬念故事为骨架，资本机制为内核，克制的黑色幽默为调味。
B 站、YouTube 与抖音精选共用正文，因此不要使用平台专属称呼。
只使用给定资料；关键事实保留 [Cxxx]；争议内容明确归因；证据不足处标记 [需要核验]。
按主角连续选择组织章节；先输出章节结构、人物动作、局面变化、章末问题与对应事实编号，再写带证据母稿；事实审计完成后另写口播净稿。
```
