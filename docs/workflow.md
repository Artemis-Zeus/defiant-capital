# 从线索到发布的工作流

## 阶段 0：线索收集

将尚未成熟的题材放入 `inbox/`。只记录足以判断价值的信息，不提前写成长文。

退出条件：线索卡完整，并能找到至少一个不是 D 级的初始来源。

## 阶段 1：选题准入

按编辑规范评估信源、冲突、反转、机制、新颖度与现实风险。

结果只能是：

- `拒绝`：不符合定位或风险明显不值得承担；
- `搁置`：有潜力但材料不足；
- `进入研究`：复制 `topics/_template/` 到 `topics/active/<story-slug>/`。

## 阶段 2：研究建档

按`skills/research-capital-story/SKILL.md`完成题材概览、角色关系、时间线、研究问题、来源表与事实表。研究阶段允许保留互相冲突的材料，但必须分别标注。

除“发生了什么”外，核心人物必须记录：身份与资源、目标与激励、当时所知、可选方案、实际行动、后果与关系反转。题材必须建立实体、时代、数字和选择四种观众参照。

退出条件：

- 核心事件拥有连续时间线；
- 决定故事成立与否的关键事实达到“已交叉验证”或“权威定论”；
- 争议点和证据空白已明确列出；
- 能用一句话说明资本或制度机制。
- 能说明主角为什么有资格成为主角，以及观众为何应在意核心金额与结果。

## 阶段 3：故事策划

按`skills/write-capital-story/SKILL.md`先写故事承诺和章节卡，再写逐字稿。章节默认由主角连续选择推进，不按机构或金融术语分类。每章至少回答：

- 观众此刻想知道什么？
- 本章提供了什么新信息？
- 冲突如何升级？
- 哪项事实支撑这一段？
- 机制解释是否紧贴剧情？

退出条件：开头钩子、关键反转、高潮、结局和机制落点均已确定。

## 阶段 4：母稿撰写

B 站与 YouTube 共用 `script/master.md`。正文保持平台中性，平台称呼、关注引导和相关推荐放入包装文件。

`master.md`是带`[C###]`标记和法律边界的编辑母稿。完成事实审计后另建`script/voiceover.md`，只保留主播实际朗读内容；不能用净稿覆盖母稿。

写作时不得：

- 补写来源中不存在的心理活动、对话或因果；
- 为了顺畅而合并不同时间发生的事件，却不加说明；
- 把后见之明伪装成当时所有人都知道；
- 用“据说”“网传”掩盖证据不足。

## 阶段 5：事实与风险复核

逐条检查母稿中的事实编号、数字、引语、时间、人物身份、司法或监管表述。完成风险检查后才能标记为可发布。

若关键事实降级为“待核验”或“存在争议”，应删除、弱化或清楚归因，不得静默保留强断言。

至少运行：

```bash
python3 scripts/audit_claims.py topics/active/<slug>
python3 scripts/audit_voiceover.py topics/active/<slug>/script/voiceover.md
```

编号闭合失败属于阻塞项；句长、报告腔和数字密度只作为实录朗读前的编辑警报。

## 阶段 6：平台包装与视觉计划

分别完成 B 站、YouTube、抖音包装；视觉素材只登记链接、用途和版权状态，不上传媒体文件。

## 阶段 7：发布与归档

记录发布时间、最终链接、标题封面版本及发布时使用的稿件版本。将目录移至 `topics/published/`。

## 阶段 8：复盘

至少在发布后 48 小时与 14 天各记录一次数据和定性反馈。区分：

- 题材本身的问题；
- 标题封面的问题；
- 开头留存的问题；
- 中段节奏的问题；
- 机制解释的问题；
- 事实或措辞受到的挑战。

复盘结论应反哺编辑规范与后续选题，而不只记录播放量。
